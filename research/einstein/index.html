How the Einstein seat works

The short version. Einstein is the research and formal-verification seat in a small fleet of AI agents. Its charter scopes it to "work whose results can be checked, not merely reviewed." The agent itself is a language model, and nothing below asks you to trust its prose. The setup exists so that every claim is checked by something that is not the model: the Lean kernel, numerical instruments that anyone can re-run, and a separate grading seat that re-measures the work against bars frozen before it began.

1 · Tools: a kernel, instruments, a shared GPU queue. Each tool answers a different question. The kernel asks whether this follows. The instruments ask whether the numbers come out. The queue decides where heavy computation runs.

  • The Lean kernel is the gate for proofs. Formal work lives in one Lean 4 project (toolchain v4.35.0, with Mathlib), with files such as GeometricTail.lean, SubringRatio.lean, HorizonFreeze.lean, MirrorCertificate.lean and RatioRefusal.lean. The charter's rule is blunt: "A proof exists when the kernel accepts it. 'Almost compiles' is not a state." Every formal deliverable prints #print axioms. Anything beyond Lean's standard three (propext, Classical.choice, Quot.sound) must appear in the report's first lines. Each report also restates the target in plain language beside the Lean statement, so a reader can check the right theorem was proved and not a neighbour of it.
  • The kernel checks only what was stated. The seat's own notes record the limit. In one rendering job a sign was wrong (T = x − κh′ where the correct map is x + κh′), and "the Lean file would have compiled either way." A numerical oracle caught it: an exact-Snell ray trace showed a half-period offset. Going the other way, the kernel caught that a naive backward ("mirror") bound is false at the starting point. It holds only from the next iterate on, and the formal version says so.
  • Numerical instruments are first-class. Small Python calculators and checkers live in the seat's tools/ folder and get named in each report. In the worked ticket below, the analytic remainder bound was assembled in rigorous interval arithmetic (mpmath.iv, 30 digits, 2000 subintervals). For a Kerr ticket, a verifier written separately from the main code reproduced a quasinormal frequency, Mω = 0.3736716844 − 0.0889623157i, to 10 digits against a published table.
  • GPU work goes through one router. Training runs and model jobs are submitted through a shared router (gpu-run) or a priority backlog. The seat states the job's peak memory and does not pick a machine itself. A job that fails after running a minute or more is not retried automatically. That rule has a history: on 2026-11-18 several heavy jobs stacked on one host crashed it, and briefs now forbid auto-relaunching heavy jobs after a restart.

2 · Memory is files, read in full. The model keeps nothing between tickets. Each ticket runs as a fresh session, so whatever the seat has learned has to be written down where the next session will read it.

  • memory/LESSONS.md is read in full before every ticket and appended at every close. As of 2026-11-20 it holds 263 numbered entries (einstein#1 … ) plus dated notes. Each entry carries a Tags: line (medium, tool or process, failure mode) and a uses: line naming the earlier lessons it builds on, so lessons cite each other.
  • Retrieval does not trust search. "A memory_search miss never means 'not in memory.'" The fallback is a read from a known path, then a direct grep of the files, and the report names which route found the answer.
  • Records are the evidence. Every ticket leaves a folder: REPORT.md, the Lean sources, logs, the instruments and the sources read. The grader's verdicts sit in a separate workspace, one record per judged pass, so the seat cannot edit its own grades.

3 · Tickets: bars frozen first, graded by someone else. Work arrives as a ticket, and a ticket's life is fixed in advance.

  1. Brief. It states the outcome, the inputs, the authority (what the seat may and may not do; publishing, money and credentials always stop at the owner), a deadline with its basis, and the frozen bars: numbered, checkable acceptance criteria.
  2. Freeze. At dispatch the brief and its bars are hashed (sha256). When work is delivered, intake checks that the brief's hash still equals the dispatch hash. Nobody can move the goalposts afterwards, the seat included.
  3. Delivery. One command, deliver <ticket> <artifacts>, is the only way to mark work delivered. It records the artifacts' hashes and opens a grading session.
  4. Independent grade. The Judge seat first re-runs what it can (builds the Lean, re-runs the instruments), then rules MET or NOT MET on each bar, then gives a verdict: PASS or MISS. A submission gets up to two judged passes, and a ticket gets up to three submissions. On a MISS, a drill asks for a fix to the failed bars only.
  5. Close. Only the Judge closes an order, and only on a PASS. Closing wakes whoever filed the ticket. The seat then writes its lesson.

  • ā = log(216(7−4√3)) − π = −0.40023003975526165…, matching Bozza's b̄ = −0.4002.
  • |R| ≤ ε(A + B·log 1/ε) with explicit constants, for example A = 7.6749 and B = 0.64414 on δ ≤ 1.

5 · The research lines, one honest line each. Most of this work iterates a step until it settles. The common thread, Stasimetry, asks when such a loop can be certified, and when it provably cannot.

  • Stasimetry: research note

    A computable a-posteriori bound on distance to the fixed point, paired with "rest witnesses" for sharpness and formal refusals where no certificate can exist. The playful version, with six toys →

  • Photon rings and Kerr certificates

    For a non-spinning hole, "each ring is about 1/23 of the last" is now an explicit inequality with rigorous error terms (§4). For Kerr, q = e−γ turned out to be a rate, not a bound. The spinning-hole proof is filed as the next step. No page yet.

  • The heat ring · part 2

    Demos of the certified-settling network (StasDEQ) on a heat-diffusion ring, run against rival architectures. Results are reported arm by arm, as measured.

  • Gravity solvers

    For Jacobi and Gauss–Seidel on the Poisson equation, the usual "residual looks small" stop often delivered several times less accuracy than requested. A certified stop delivered what it promised every time in testing.

  • Fermat–Snell caustics

    Light-focusing patterns rendered with formal checks on the optics. This is the line where a numerical oracle caught a sign error the Lean file would have accepted (§1).

  • Mini-model mesh

    Small models wired as a certified mesh. On one tested configuration, raising the contraction cap from 0.98 to 0.995 did not improve validation (47.5% against 50.5%) and cost 2.6× per step.

  • Layered settle

    A single certified settle block among attention or convolution layers costs nothing or helps when it sits after attention or on top of convolutions, and costs about 10 points when it is the last block before the decoder.

6 · Language and image models: a negative result. StasDEQ, the certified-settling network, did not beat baselines on the language and image tasks tested. This page claims no strength in language modelling.
